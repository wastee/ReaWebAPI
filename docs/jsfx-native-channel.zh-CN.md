# JSFX 原生通道

[English](jsfx-native-channel.md) · [Web UI 接入](jsfx-webui.zh-CN.md)

可选原生通道通过现有 `jsfx` 服务提供 JSFX 遥测、结构化状态、命令和二进制资源。通道使用 REAPER 已加载的 JSFX 引擎，参与接入的插件需导入 `reaweb_jsfx.inc`。纯参数 Web UI 无需修改 DSP。

## 传输路径

```text
JSFX @block / @sample
  ↔ 命名 gmem 槽位
  ↔ 同一 JSFX 引擎中的私有辅助实例
  ↔ 扩展专用暂存区
  ↔ 现有 Service / Stream 传输
  ↔ Hosted WebView
```

桥接校验 `JesusonicAPI` 版本 `0xf0f01091` 及必要的宿主 EEL 导出。私有辅助实例不占用工程轨道、FX 槽位或窗口。宿主 EEL 仅在辅助调用返回后访问暂存区，不直接读取生产者正在使用的数据。不支持的引擎保留参数模式，原生能力返回 `UNSUPPORTED`。

Windows、macOS 和 Linux 上，每个通道引擎编译覆盖 256 个值的暂存读写程序。C++ 按块更新偏移和长度并复用程序，末块仅访问实际包含的值。程序生成与编译成本因此保持有界，数据包上限、共享内存布局及同步规则不变。暂存通过宿主 EEL 注册变量访问，不依赖私有 VM 内存布局。

`JesusonicAPI` 是面向 REAPER 的导出接口，并非承诺稳定的第三方 Extension SDK 契约。宿主升级需要兼容性验证。桥接不替换 JSFX 引擎、不修改回调，也不访问私有实例布局。

## 实例绑定

宿主校验工程生命周期、归属者 GUID、FX GUID 和源文件身份。显式预留的传输滑块提供 EEL 代次。

1. 宿主读取目标滑块，在已分配的 gmem 槽位中发布挑战。
2. 活动 EEL 实例匹配自身代次，取得槽位并分配新代次。
3. JSFX 将新回复写入自身传输滑块。只有目标实例的读回值与槽位回复一致，宿主才接受绑定。

复制或恢复的滑块值本身不能建立绑定。初次连接及重新连接不调用宿主参数写入，不创建撤销记录，也不使工程变脏。DSP 未被调度时等待握手回复，不自动启动播放或修改音频设备。

同一 VM 的序列化恢复通过已有槽位续约。重建后的 VM 在有限续约等待后重新绑定。新代次使旧操作、快照和传输票据失效。实际持久状态或资源修改仍会通知 REAPER 并参与撤销，该通知与连接建立分开处理。

Web UI SDK 在 Session 更换或可恢复的传输关闭后重建已打开的 DSP 流并保留订阅，有效流暂时无数据时保持连接。生命周期与重试行为见 [Web UI 流恢复说明](jsfx-webui.zh-CN.md)。

在 `@slider`、每次 `@block` 服务调用前及 SDK 序列化后执行 `sliderN=reaweb_jsfx_handshake(sliderN)`。该专用滑块不得用于自动化、其他参数或网页编辑。

## 同步与边界

[官方 JSFX 实现](https://github.com/justinfrankel/jsfx/blob/main/jsfx/effectproc.cpp)为 `atomic_*` 使用模块级互斥锁。桥接两端在同一引擎中执行，所有权切换使用同一同步原语。数据复制在互斥锁外进行，复制期间槽位由当前端独占。该通道不是无锁实现。

- 音频侧仅尝试一次槽位获取。槽位忙或队列满时丢弃遥测或延后控制工作，不等待网页。
- 缓冲预分配并预触页。遥测每包最多 4096 个值，每实例最多八包。控制负载最多 8192 个值。
- 私有辅助实例仅初始化一次命名空间。无订阅时按 20 ms 状态间隔检查队列。块快照没有待处理命令时，DSP 服务跳过命令槽位获取。
- 状态序列化使用独立门控。序列化占用门控时，音频处理跳过 SDK 状态工作。保存可能等待正在执行的有界状态复制。

声明的 gmem 范围为 `[base, base + 2170944)`，包含 32 个实例槽位和私有暂存区。SDK 还预留 32768 个本地内存单元。状态与资源双缓冲不得与该范围或彼此重叠。

相同 gmem 名称表示共享内存，不表示 FX 实例身份，也不隔离任意其他 JSFX 代码。保留现有插件的命名空间，并声明未使用的范围。参见[官方共享内存说明](https://www.reaper.fm/sdk/js/basiccode.php)。

## 执行契约

流仅发布插件显式选择的数据。状态写入使用 schema 校验及修订号检查。命令仅在 DSP 确认后完成。资源上传先暂存并校验，再在块边界切换。持久数据使用插件的 `@serialize`。

bypass、离线、设备停止，以及未调度的 Take 或输入 FX 可能暂停执行。超时不代表运行中的命令已经停止。持续操作和所属 MIDI 音符在 DSP 恢复时清理。页面可见性与 DSP 调度分别管理。

音频性能取决于宿主、设备和负载。回调处理耗时、发布至消费者的延迟、设备报告延迟属于不同路径。`GetUnderrunTime` 在宿主支持时提供最近欠载时间戳，不提供准确事件计数。参见[官方 API 文档](https://www.reaper.fm/sdk/reascript/reascripthelp.html#GetUnderrunTime)。
